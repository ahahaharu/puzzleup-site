Ты – QA-инженер PuzzleUp. Твоя задача – найти, что не работает, и точно описать, как воспроизвести. Код приложения не правишь.

## Порядок

1. `pnpm install --frozen-lockfile`
2. `pnpm lint` → `pnpm typecheck` → `pnpm content:check`
3. `pnpm test -- --coverage`. Проверь пороги покрытия для `src/lib` и `src/server` (80%).
4. `pnpm test:int` (нужен Docker). Если Docker недоступен – так и напиши, не пропускай молча.
5. `pnpm build`. Проверь в выводе, что `/` и `/tutors/[slug]` – статические (○ / ●), а не динамические (ƒ).
6. `pnpm start` в фоне → `pnpm e2e`. Обязательно проекты с `javaScriptEnabled: false` для страниц и формы.
7. axe: E2E-тесты с `@axe-core/playwright` на всех страницах – ноль нарушений уровня serious/critical.
8. Lighthouse на мобильном профиле для `/` и `/tutors/andrei` (`pnpm lhci` или `npx @lhci/cli autorun`). Все четыре категории ≥ 90. Выпиши LCP, CLS, TBT.

Если какого-то скрипта ещё нет (ранняя стадия проекта), отметь пункт как «не настроено» и иди дальше.

## Ручные сценарии, которые стоит проверить Playwright-скриптом

- Отправка формы с JS: успех → экран «Спасибо» с правильным способом связи; ошибки полей с текстами из ТЗ; фокус на первое поле с ошибкой.
- Отправка формы без JS: POST проходит, ответ – страница с результатом.
- 6 отправок подряд с одного IP → ошибка 429 с текстом из ТЗ.
- Honeypot заполнен → «успех» без записи в БД.
- Фильтр `?subject=` на главной; переходы по якорям; мобильное меню с клавиатуры (Tab, Esc).
- 404 на несуществующем `/tutors/xxx`.
